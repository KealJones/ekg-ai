# v0.5 Phase-0 blocker: depth alone is not an operational search budget

No v0.5 teaching or scored evaluation was run.

Claude's constant-free observational enumerator collapses expressions by denotation and therefore reports small depth-3 spaces (213–1,787 behaviors for the proposed taught primitives). The actual EKG synthesizer enumerates syntactically distinct expressions and deduplicates only exact JSON expression identity. It has no candidate/node/memory/time budget; `maxDepth=3` is the only budget.

Engine-isolation probes using the frozen v0.5 benchmark and a 512 MB Node heap found:

- `padded_block_size:F1_arg_composed:000` (`List<String>, Int, Int`) — OOM before depth-3 completion.
- `pair_name_width:F1_arg_composed:000` (`String, String, Int, Int`) — OOM before depth-3 completion.
- `mod_int:F1_arg_composed:000` (`Int, Int, Int`) — OOM before depth-3 completion.
- `merged_block_size:F2_under_base:000` (`List<String>, List<String>, Int`) — completed in ~465 ms, 39,690 evaluated output-typed candidates, unsolved.
- `interleave_cost:F2_under_base:000` — same ~465 ms / 39,690 candidates, unsolved.

This is not evidence for or against the taught abstractions. It is a spec/engine compatibility failure. P0-11 through P0-13 cannot be truthfully certified on the real engine under the preregistered "depth <= 3" budget because depth 3 is not operationally bounded for all benchmark signatures.

Changing the synthesizer now (behavioral deduplication, candidate cap, beam search, time cap, memory cap, etc.) would alter the system under test. The next methodology decision should therefore be made before any teaching event.
