# v0.9.4 — Memory graph reset

This checkpoint removes the external graph-database detour and returns EKG to the original zero-dependency in-process graph backend.

## Current architecture

- `MemoryGraphStore` is the sole active `GraphStore` implementation.
- No external graph database, database server, JVM requirement, native database package, or remote database integration is part of the runtime.
- Search v2, self-healing/lived-experience recovery, curriculum work, semantic language graph, object/JSON substrate, and the language/Blueprint hypothesis remain intact.
- `node_modules` and generated `dist/` are excluded from the checkpoint.
- Historical exhaustive Phase-0 experiments remain outside the normal fast test lane.

## Honesty boundary

`MemoryGraphStore` is durable only for the lifetime of the running learner instance. It does not yet provide restart persistence. A future portable snapshot/file adapter can add that without changing EKG's graph semantics.

## Why this reset

The immediate development priority is a learner that can actually be executed, educated, repaired, and tested end-to-end in constrained environments. Database sophistication is deferred until it demonstrates value that outweighs its operational cost.
